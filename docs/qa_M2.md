## 새 발견 — 결함 4 [중] 시연 리허설 컷 2의 레버 OFF 전달 시각이 회차마다 들쭉날쭉

- **재현**: `demo/rehearsal.py`를 3연속 실행(M2용 최종 리허설 겸용) 후 `demo/rehearsal_summary.py`로 두 로그씩 비교(1v2 · 2v3 · 1v3, 전부 교차 비교).
- **증상**: 컷 2(`cut2_wait_go`, 대본상 OFF는 "hold anchor + 0.5초")의 `turnSignal=OFF` 실제 도착 시각이:
  - 1회차 6.18s · 2회차 5.66s · 3회차 6.00s (hold anchor 시각 자체는 1·2회차 5.15s로 똑같았는데도 OFF가 1회차만 1.03초 뒤, 2회차는 0.51초 뒤에 옴)
  - D4가 정한 동일성 기준(`rehearsal_summary.py`의 "같음 = 차이 ≤ 0.15초")을 **세 비교 전부에서 cut2가 못 넘음**. cut1·cut3는 전부 기준 안(최대 0.12초 차)이거나 동시각 줄 정렬 차이뿐 — cut2만 반복적으로 벗어남.
  - conductor가 보고하는 자체 "late="(명령을 보낸 시각이 예정보다 얼마나 늦었는지)는 세 회차 모두 4~11ms로 정상 — 즉 **conductor는 제때 PUT을 보냈는데, 엔진이 그 신호를 받은 시각이 회차마다 0.3~0.5초씩 어긋난다.**
- **원인 추정(미확인)**: qa_M1 결함 1과 같은 계열 — VC 웹 API(이번엔 turn-signal PUT) 전달 지연/드롭으로 보임. 결함 1 대응으로 D5가 넣은 속도(`speed`) PUT 확인·재시도(`conductor.set_speed`)는 **turn-signal PUT엔 적용 안 돼 있다** — `play_vc`(일반 신호 PUT 경로)는 결과를 확인하지 않고 쏘기만 한다.
- **영향**: 기능은 매회 정상 동작(쉼표→OFF→재개 순서·결과 전부 맞음, 쉼표 취소나 미발생 같은 진짜 오류는 0). 다만 **컷 2 영상의 초 단위 자막/타이밍을 대본(ⓑⓒⓓ)대로 맞추기 어려울 수 있다** — 11/10 실촬영에서 컷 2만 여러 번 다시 찍어야 할 가능성.
- **제안(참고용, 적용은 개발 담당)**: `demo/conductor.py`의 `play_vc`에도 `set_speed`와 같은 확인(로그에서 해당 `Comma: turnSignal=…` 발생을 짧게 기다렸다가 없으면 재전송)을 넣는 쪽을 검토.
- 코드는 고치지 않음 — 재현만 보고. 근거: 스크래치패드 `m2_rehearsal_01~03_logcat.txt` · `m2_summary_1v2.txt`·`m2_summary_2v3.txt`·`m2_summary_1v3.txt`(세션 종료로 사라짐 — 재현 필요하면 3연속 리허설 + `rehearsal_summary.py` 교차비교로 다시 재현 가능).
