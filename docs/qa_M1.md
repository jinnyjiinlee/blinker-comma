## 결함 목록 (심각도순)

### 1. [상] 시연 대본 리허설에서 컷 1의 쉼표가 통째로 안 걸리는 경우가 있다 — VC 속도 명령이 적용 안 됨

- **재현**: `demo/rehearsal.py`를 연속 3회 돌림(새 설치마다). 1·3회차 성공, **2회차 실패**.
- **증상**: 컷 1 준비 줄(`gear PARK → app play → gear DRIVE → speed 40`, 0.5초 간격) 중 마지막 `speed 40` PUT이 VC에서 `200 OK`를 받았는데도 차의 속도가 끝까지 0으로 남았다. 그 상태에서 BlinkRight가 들어오면 엔진이 설계대로 `lever=ON speed=0 → no comma`(R3)를 내고 쉼표가 안 걸린다 — **엔진은 옳게 반응했고, VC가 보낸 속도 값이 적용 안 된 것**.
- **근거 로그**: `qa_run2_logcat.txt`(스크래치패드) — relaunch(17:43:08) 이후 `SpeedChanged`가 한 번도 40(11.11m/s)으로 안 바뀜. 같은 조건의 1·3회차 로그(`qa_run1_logcat.txt`·`qa_run3_logcat.txt`)는 GearChanged DRIVE 뒤 바로 SpeedChanged(11.11m/s)가 찍힌다. 대조:
  - 성공(run1) `17:41:39.230 GearChanged DRIVE` → `17:41:39.769 SpeedChanged speedMps=11.11`
  - 실패(run2) `17:43:20.863 GearChanged DRIVE` → (끝까지 SpeedChanged 없음) → `17:43:25.423 lever=ON speed=0 → no comma`
- **영향**: 11/10 실제 영상 촬영도 같은 conductor·VC 경로를 쓴다. 3회 중 1회 꼴로 이 사고가 나면 촛팅 리허설/본 촬영에서 그대로 재현될 수 있다.
- **원인 추정(미확인)**: VC 웹 API 자체의 산발적 드롭으로 보임(이번 재현에서 vc_put은 예외 없이 200을 받았으므로 503/하트비트 끊김과는 다른 증상 — `docs/signals_measured.md` 「첫 값(등록 직후)」 절의 중복/지연 현상과도 다름, 새로운 증상). 코드 수정 없이 보고만 함.
- **제안(참고용, 적용은 개발 담당)**: conductor 쪽에서 속도 PUT 뒤 앱 로그의 `SpeedChanged`(비0)를 짧게 기다렸다가 없으면 재전송하는 확인 루프를 두거나, VC 호출 자체에 짧은 재시도를 둔다.

### 2. [상] 콘텐츠 팩이 아직 「측정용 합성음」 — 퍼블릭 도메인 영어 낭독으로 교체 안 됨

- **확인**: `app/src/main/assets/packs/en1/pack.json`의 `credit`이 `"측정용 합성음(낭독 팩 교체 전)"`, `clips[].text`가 `"probe tone N"`. `s01.m4a` 실제 재생 길이 2.6초 = pack.json의 `durationMs` 그대로(순음 톤). `CREDITS.txt` 없음. 이 팩을 만든 커밋은 D2의 `da4da3d` 하나뿐(이후 교체 커밋 없음).
- **실물 확인**: P 화면 UI 덤프에 `text="낭독 출처 · 측정용 합성음(낭독 팩 교체 전)"`, `text="측정 팩"`이 그대로 뜬다. 지금 상태로 스크린샷·영상을 찍으면 그대로 노출된다.
- **SPEC 근거**: 「콘텐츠 팩」 절(「문장당 2~6초 … 퍼블릭 도메인 영어 낭독」)·「위험」 절(「콘텐츠 라이선스: 고른 녹음의 PD 표기를 원문으로 확인하고 CREDITS에 URL 기록」) · `CONVENTIONS.md` 테스트 대장 마지막 줄 「시나리오 테스트를 실제 낭독 팩 길이로 — 미작성(낭독 팩 들어온 뒤)」.
- **영향**: MVP 범위(「앱 안 영어 낭독 1팩」)가 아직 안 채워졌다. 컷 1 영상 시각(ⓐ2.0·ⓑ2.6·ⓒ3.7·ⓓ4.5)도 지금 팩(문장 A=3.0초)이 아니라 2.6초짜리 실제 문장으로 다시 재야 한다 — 이미 progress.md D4 「남은 일」에 적혀 있던 항목.
- **새로 발견한 것은 아님** — 본인들이 이미 추적 중인 미완료 항목이지만, 11/8 시연 동결까지 남은 일수가 적어 상으로 분류.

### 3. [중] engine 경계 케이스: 팩 마지막 문장이 레버 ON(예약 중)으로 끝나면 쉼표 없이 조용히 멈춘다

- **재현**: 측정 팩(8문장) 전체를 재생시키고 마지막 문장(s=8) 재생 중 BlinkRight를 켠 채 유지. 로그:
  ```
  00:47:53.201 Comma: turnSignal=RIGHT
  00:47:53.201 Comma: moving → comma armed
  00:47:55.120 Comma: pack end → stop          ← 여기서 바로 정지, 「clipEnd lever=ON → hold」 없음
  00:47:55.209 Comma: turnSignal=OFF
  ```
- **원인**: `engine/.../reader/OnClipEnded.kt`의 `onClipEnded`가 `next >= state.clipCount`(마지막 문장)를 `phase.armedAt != null`(레버 ON 예약)보다 먼저 검사해 무조건 `finish()`로 간다. R1(「레버 ON+이동 중이면 예약, 문장 끝에 닿으면 멈춘다」)이 "다음 문장이 있을 때"로만 암묵적으로 좁아져 있다.
- **영향**: 실제 팩은 30~40문장이라 1분짜리 시연 영상에선 거의 안 걸리지만, 실제 사용(긴 드라이브로 팩을 다 들은 뒤 마지막 문장에서 차선 변경)에서는 사용자가 예상한 ⏸(쉼표)가 안 뜨고 그냥 멈춘다. 쉼표 카운트도 안 올라간다.
- **테스트 없음**: `EdgeScenarioTest.kt`에 R2(취소)·R4(상한)·R10(포커스) 경계는 있지만 「마지막 문장+예약」 경계는 0건.
- 코드는 고치지 않음 — 재현만 보고.
