> 이번 단계(U0)는 **감사·설계만** — 코드 수정 0. 현재 모든 상태를 캡처해 차량 HMI 디자이너 시각으로 비평하고, 개선 목록·와이어·토큰 변경안·애니메이션 명세·안전 근거를 정리한다. 실제 구현은 다음 단계(U1 이후) 대표 승인 후.

## 1. 비평 (화면별)

### D 화면 — 쉼표 없음 (`U0_05`) — 허전함 최대
1682×1210dp 중 900dp(카메라 780dp 제외)가 **완전한 검정**. 브랜드 신호 0, 움직임 0, 「앱이 떠 있다」는 증거가 전혀 없다. 시연 영상에서 이 구간(대부분의 주행 시간)이 비게 보이는 게 바로 이것 — 대표 지적의 핵심 원인.

### D 화면 — 쉼표(hold) (`U0_06`, `U0_07`) — 위계는 명확, 정보값 0
⏸ 96dp 하나가 900dp 폭 한가운데(카메라 오른쪽) — 주의를 끄는 유일한 요소라는 점에서 **위계는 맞다**(원칙 1 그대로 유지됨). 그러나:
- **발견 1(신규 실측, 중요)**: 레버 LEFT와 RIGHT를 둘 다 실측했는데 **카메라 오버레이 위치·⏸ 위치가 완전히 동일**하다(`U0_06` vs `U0_07` 픽셀 비교). 즉 지금 화면은 "왜 멈췄는지"의 방향 단서를 전혀 주지 않는다 — 대표가 요청한 "깜빡이 방향과 같은 쪽에서 들어오는 쉼표"의 정반대 현재 상태.
- ⏸와 카메라가 서로 다른 섬처럼 떨어져 있어 "하나의 화면"이라는 느낌이 약하다.
- 등장/퇴장이 즉시 컷 전환(애니메이션 0, SPEC 명시) — 정보 전달은 정확하지만 "부드러운 전환"은 없다.

### P 화면 (`U0_03`, `U0_04`) — 구조는 안정적, 공백 과다
좌: 표지·사용법·카운트·토글·출처 / 우: 재생판 — 레이아웃 자체는 Pleos 카드 패턴과 잘 맞는다. 문제는 여백 배분:
- 좌측 컬럼 `ParkScreen.kt`의 `Spacer(Modifier.weight(1f))` 하나가 HowItWorks(사용법 3줄)와 TodayTally(오늘 카운트) 사이를 1210dp 높이의 1/3 가까이 벌려 놓는다 — 두 블록이 "같은 화면의 다른 이야기"처럼 분리돼 보인다.
- 우측 판 `PlaybackPanel.kt`의 `Spacer(weight=1f)` 2개(제목↔버튼, 라벨↔상태줄)도 동일 패턴.
- 132sp 숫자(오늘 N문장·M쉼표)는 크기 위계는 완벽하지만 **그 숫자를 설명하는 보조 그래픽이 없어** "그냥 큰 숫자"로 소비된다.
- 브랜드 모티프(쉼표 심볼)가 `BrandHeader`에만 1회 등장 — 화면 전체 톤에 스며들지 않는다.

### 권한 안내 — 우선순위 낮음
글 3줄 + 버튼 1개에 비해 화면이 커서 위아래 공백이 크다. 1회성 화면이라 임팩트는 작음 — 이번 라운드 개선 목록에서 제외.

### 런처 아이콘 (`U0_10`) — 수정 불필요
Pleos 다른 앱 아이콘들(모노크롬·2색 이하)과 톤이 맞고 식별성도 좋다.

## 3. 개선 우선순위

### P0 — 이번 라운드 권장(안전 영향 없음, 임팩트 큼, 대표 승인 필요 — 4절 참고)
1. **방향성 쉼표 진입**: ⏸가 레버 방향과 같은 쪽 가장자리에서 들어와 같은 중앙 자리에 정착(궤적만 다르고 최종 위치·크기는 동일 — 발견 1 해소).
2. **쉼표·재개 1회성 전환**: 등장 260ms 페이드+슬라이드, 퇴장 180ms 페이드(루프 없음, 아래 애니메이션 명세).
3. **D 읽는 중 정적 워터마크**: 쉼표 심볼을 아주 옅게(12% 불투명도) 배경에 고정 배치 — 애니메이션 없음, "앱이 떠 있다"는 신호만 상시 제공.
4. **P 화면 Spacer 정리**: weight(1f) 공백을 고정 간격(`CommaSpace.xlarge`)으로 교체 + 사용법↔카운트 사이에 "오늘 쉼표 타임라인"(작은 점 n개, 호박색) 추가.

### P1 — 검토 후 2차
5. P 화면 재생 버튼 둘레에 **정적** 진행 링(현재 문장 내 위치를 세그먼트로, 연속 회전 없음 — Tick마다 다시 안 그리고 문장 전환 시점에만 갱신) — "낭독 진행을 보여주는 큰 원형" 요청을 정차 화면에서 안전하게 구현.

### P2 — 보류(비권장, 이유 명시)
6. **D 화면에 연속 원형/파형 애니메이션을 넣는 안은 보류 권장.** 지속 루프는 주변시야 모션 포착 위험이 있고(아래 5절), SPEC 원칙 1 "애니메이션 0"이 원래 이 이유로 정해진 것으로 추정됨. P0-3(정적 워터마크)으로 "살아있는 느낌"을 대체.
7. **주간/야간 대비 테마**는 이번 라운드에서 만들지 않는다 — NIGHT_MODE는 SPEC이 채택한 신호 목록에 없고(「쓰는 신호」 표 밖), 새 신호를 끌어오려면 권한 승인·실측이 새로 필요해 11/8 동결 일정과 맞지 않는다. 대신 기존 `Contrast.kt`의 `flare` 파라미터(햇빛 반사 모델)가 이미 "밝은 환경에서도 대비 4.5 이상"을 보장하므로, 밝은 환경 대응은 이미 돼 있다고 결론.

## 4. 애니메이션 명세 — 1회성 전환만, 지속 루프 금지

원칙: SPEC 원칙 1("애니메이션 0")을 **"지속 루프 0"으로 재해석**하고, 상태가 바뀌는 "사건"(쉼표 시작/해제)에 한해 300ms 이하 1회성 전환만 허용한다. **이 재해석 자체가 SPEC 변경이므로 구현 전 대표 승인 필요.**

| 전환 | 트리거 | 효과 | 시간 | 곡선 |
|---|---|---|---|---|
| 쉼표 등장 | 실제 소리가 멎는 순간(`ShowHoldGlyph(true)`, 원칙: 명령 순간 아님) | translateX(레버 방향별 ±120dp → 0) + alpha(0→1) | 260ms | FastOutSlowIn(급가속 없음) |
| 쉼표 퇴장 | 실제 소리가 다시 나는 순간 | alpha(1→0), 이동 없음 | 180ms | FastOutLinearIn |
| D 워터마크 | — | 없음(정적, opacity 고정 12%) | — | — |
| P 진행 링 | 문장 시작/종료 시점에만 값 갱신 | 없음(연속 회전·Tick마다 리드로잉 금지) | — | — |

좌/우 진입 오프셋 120dp는 `CommaSize.holdGlyphEnterOffset`(신규 토큰)로 — 카메라 폭 780dp 안쪽으로는 들어가지 않는 값(96dp 아이콘 + 120dp 오프셋 = 216dp, 카메라 밖 공간에서 소화됨, 좌표 재검증은 구현 단계에서 `CommaThemeFloorTest` 류로 고정).

## 5. 안전 근거

- **NHTSA 2초/12초**(research/deep_v3/platform.md): 1회성 전환 260ms는 단일 glance(1.5~2초) 안에 끝나며, 반복 글랜스를 요구하지 않는다.
- **Pleos DO 허용 범위**(platform.md "② 정차 중에만 되는 것" 각주): "Pleos는 Google SA-1 애니메이션 금지 규칙이 없고 DO 선언 자체 UI를 주행 중에도 허용"하지만, 이는 정차 전용 설정·로그인 UI를 주행 중에도 띄울 수 있다는 뜻이지 "애니메이션을 마음껏 넣어도 된다"는 뜻은 아니다 — SPEC 원칙 1(글자 0·터치 0)은 그대로 유지, 이번 제안도 그 위에서만 움직인다.
- **주변시야 모션 포착 리스크**: 연속 루프(워터프·파형·회전 진행바)는 운전자의 주변시야를 끌어당길 위험이 있다는 것이 SPEC이 원래 "애니메이션 0"을 택한 이유로 추정된다. 이번 제안은 그 정신을 지키기 위해 **지속 루프를 전부 배제**하고 "사건 1회성 전환"과 "완전 정적 모티프"만 썼다.
