## 공통 지적 (우선순위 — 겹치는 심사위원 수 기준)

### 1. 주행(D) 화면 쉼표 워터마크·상태 표시가 약하다 — 3명 전원
- UX: 「워터마크가 거의 안 보일 정도로 옅어(어두운 올리브색) 화면이 '비었다'는 인상」(U2_03·U2_05)
- HMI: 「쉼표 워터마크가 화면 우측 끝에서 꼬리 부분이 잘려 보임」(U2_03, frame_23/27/71/76)
- 큐레이터: 「주행 화면이 쉼표 워터마크 하나만 있는 거의 완전한 빈 검정 화면 — 스토어 스크린샷으로 단독 노출되면 정보가 0」

### 2. 깜빡이 ON 때 블라인드스팟 카메라 영상과 앱 쉼표 표시가 겹쳐 보인다 — 2명(UX·HMI)
- UX: 「블라인드스팟 카메라 영상 위에 오렌지 일시정지 아이콘이 겹쳐 뜨는 배치, 도로 영상과 UI가 포개져 시선을 끈다」(U2_04·U2_06)
- HMI: 「카메라 영상(움직이는 차·거리 장면)과 앱 요소가 동시에 화면을 분할 점유 — 차로변경 중 그 자체로 주의를 끄는 요소」

### 3. 쉼표 중 상태 표시가 작고 식별성이 낮다 — 2명(HMI·큐레이터)
- HMI: 「작은 주황 막대(⏸) 아이콘 하나뿐 — 1초 미만 흘끗 보기로는 식별이 쉽지 않음」
- 큐레이터: 「레버 조작에 따른 재생/정지 전환이 아이콘 교체만으로 표현돼 시연 체감 속도가 느림」

### 4. 예외 상태(「속도 신호 확인 안 됨」) UI가 메인 디자인 톤과 어긋난다 — 2명(UX·큐레이터)
- UX: 「경고성 텍스트가 일반 안내와 동일한 작은 회색 글씨 — 심각도가 구분되지 않는다」(U2_07)
- 큐레이터: 「작은 회색 원 아이콘 + 텍스트 한 줄로, 정차 화면의 다른 완성도 높은 요소와 톤이 어긋난다」

### 5. 앱 브랜드 식별 요소(로고·이름)가 어떤 캡처에도 없다 — 1명(큐레이터), 단 스토어 입점 기준 치명적
- 「캡처 16장 전부에 앱 로고·이름이 단 한 곳에도 없다 — 스토어 입점 심사에서 '어떤 회사·무슨 앱인지' 식별이 안 되는 건 치명적」

## 단독 지적 (참고)

- UX: 좌측(정차 패널 — 흰 배경·클러스터풍 렌더)과 우측(앱 — 검정·오렌지) 색 테마가 완전히 분리돼 하나의 제품처럼 안 읽힘 / 「오늘 N문장·M쉼표」 숫자-레이블 밀착도 약함.
- HMI: 재개 전환이 매끄럽지 않음(frame_49에 화살표·⏸ 잔상) / 실외 직사광·눈부심 조건의 저대비 워터마크 가독성 검증 자료 부재.
- 큐레이터: 권한요청 화면(frame_05)의 텍스트 블록 상하 여백 불균형.

## 이번 단계 범위

심사·기록만 — **코드 수정 0**. 적용 여부·우선순위 채택은 다음 라운드(대표 승인 필요, M8 upgrade_plan 4-1·4-2의 「Mia 설계 → UI 개선 실행기」 흐름과 합쳐 검토 권장 — 공통 지적 2·3번이 M8 4-2 「쉼표 N 배지」 제안과 같은 방향).

## 한계

- 심사위원은 정지 이미지만 봤다 — 실제 전환 애니메이션(260ms/180ms)의 매끄러움은 체감 못 함(HMI·UX 둘 다 이 한계를 직접 지적: "연속 프레임만으로는 모션감 확인 안 됨").
- 연속 프레임 9장은 ffmpeg 키프레임 스냅으로 로그 시각과 ±수백ms~1초 어긋날 수 있어 정밀 동기화 라벨이 아님(프롬프트에 명시해 전달).
- 3명 다 Claude 기반 에이전트 페르소나이고 실제 해당 직군 인물이 아니다 — 참고용 블라인드 2차 의견으로만 쓸 것.

## U3 반영 결과 (코드 작업, 대표 승인 범위 내)

공통 지적 1~4는 코드로 반영했다(상세는 `docs/ui_plan.md` 10절) — 워터마크 가시성·클리핑, 카메라 경계선,
「쉼표 N」 배지(M8 4-2와 합쳐 반영), 「확인 안 됨」 칩 스타일.

**5순위(브랜드 식별 요소 없음)는 반영하지 않았다** — D 화면에 로고·앱 이름을 넣으려면 원칙 1("글자 0")의
재해석 범위를 "숫자+짧은 단어 하나"(이번 배지)보다 더 넓혀야 하고, 이건 또 다른 대표 승인 사이클이 필요한데
11/8 시연 동결까지 여유가 빠듯하다. 대신 운영적으로 해결하는 쪽을 권장한다: 스토어 제출용 캡처 묶음을 고를 때
로고가 있는 P 화면(`BrandHeader`, `U3_02`·`U3_03` 등)을 반드시 포함시킨다 — D 화면 캡처만으로 스토어 자료를
구성하지 않으면 지적한 문제 자체가 발생하지 않는다.
